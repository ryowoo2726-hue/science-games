# 부력 탐험

태블릿을 자동차 핸들처럼 돌려 물과 중력의 방향을 바꾸고, 잠수정 탱크의 물을 조절해 탈출하는 과학 게임입니다. **360° 조작, 연속적인 입자 물, 11개 미로, 가시와 누수·정비소, 스위치 수문, 밀도가 다른 액체, 전체 화면**을 지원합니다.

**[게임 열기](https://ryowoo2726-hue.github.io/science-games/games/buoyancy/)**

## 실행과 개발

Node.js 22.12 이상이 필요합니다. 검증 환경은 Node 24입니다.

```sh
npm ci
npm run dev
```

표시되는 주소를 브라우저에서 엽니다. 기본 주소는 `http://localhost:5173/`입니다.

Google Drive 가상 드라이브에서 npm 설치가 `EBADF`나 `EPERM`으로 실패하면 **`개발실행.cmd`**를 실행하세요. 원본 소스를 `%LOCALAPPDATA%/CodexProjects`의 프로젝트 전용 폴더에 복사해 실행합니다. 원본 편집 후 다시 실행하면 수정 내용이 복사됩니다. 사용 중인 포트는 피해서 실행합니다.

```sh
npm test
npm run build
npm run preview
```

완성된 `dist`가 있으면 **`미리보기.cmd`**로 설치 없이 미리 볼 수도 있습니다. 기본 주소는 `http://localhost:4173/`입니다. `dist/index.html`은 HTTP 서버로 실행합니다. GitHub에는 소스만 올리며 `dist`, `node_modules`, ZIP은 제외합니다.

## 조작

| 기능 | 터치·마우스 | 키보드 |
| --- | --- | --- |
| 360° 기울기 | 센서 또는 −180°~+180° 슬라이더 | ← → 계속 누르기 |
| 탱크 물 빼기 | 왼쪽 아래 버튼 길게 누르기 | W |
| 탱크 물 채우기 | 오른쪽 아래 버튼 길게 누르기 | S |
| 정지·계속 | 위쪽 정지 버튼 | 스페이스 |
| 0° 보정 | 과녁 버튼 | 버튼에 포커스 후 Enter |
| 단계 선택 | 위쪽 단계 목록 | 목록에 포커스 후 방향키 |
| 전체화면 | 네 모서리 모양 버튼 | 버튼에 포커스 후 Enter |

각도 표시는 0°~359°입니다. 중력은 0°에서 아래, 90°에서 오른쪽, 180°에서 위, 270°에서 왼쪽을 향합니다. 슬라이더의 양 끝은 같은 방향이며 각도 경계를 건너갈 때 짧은 방향으로 이어집니다. 센서와 키보드는 여러 바퀴 연속 회전할 수 있습니다.

태블릿은 **화면을 정면으로 바라보며 세워 잡고** 센서로 시작하세요. 첫 유효한 자세를 기준으로 잡습니다. 화면이 거의 수평이면 화면 안쪽 중력의 방향을 구분하기 어려워 마지막 유효한 자세를 유지합니다. 과녁 버튼으로 현재 자세를 다시 0°로 잡을 수 있습니다. HTTPS와 기기별 센서 권한이 필요하며 거절·무응답·연결 중단에서는 수동 조작으로 전환합니다.

전체화면을 지원하면 시작할 때 요청하고, 가능한 브라우저에서는 가로 방향을 유지합니다. 지원되지 않아도 브라우저 표시 영역을 가득 채웁니다. 센서 모드에서는 슬라이더를 숨깁니다. 화면 크기를 바꿔도 물리 좌표와 미로 비율은 유지됩니다.

탱크 버튼은 잠수정 내부에만 작용합니다. 비움부터 가득까지 약 3.85초 걸립니다. 손을 떼거나 터치를 취소하거나 포커스를 잃으면 즉시 멈춥니다. 두 버튼을 함께 누르면 상쇄합니다. 다른 탭으로 이동하면 일시 정지됩니다.

출구에 닿으면 완료 시간과 다음 단계 버튼을 표시합니다. 마지막 단계 이후에는 처음부터 다시 시작할 수 있습니다. 단계 목록에서 모든 미로를 바로 선택할 수 있으며 재시작은 현재 단계의 물·잠수정·시간을 초기화합니다.

## 11개 단계

11개 단계와 기존 단계 ID를 유지합니다. 첫 단계는 기본 부력 조작을 익히고, 이후에는 협곡·수직 하강·저수지·나선·갈림길·역방향 경로를 서로 다른 퍼즐과 조합합니다. 난이도는 가시 회피, 스위치 탐색, 밀도 조절, 여러 수문을 순서대로 여는 방식으로 높아집니다.

| 단계 | 이름 | 주요 변화 |
| --- | --- | --- |
| 1 | 첫 번째 잠수 | 기본 3개 통로 |
| 2 | 산호 협곡 | 섬과 절벽을 돌아가며 가시·정비소 익히기 |
| 3 | 첫 번째 수문 | 위쪽 스위치로 두 방 사이의 수문 열기 |
| 4 | 가시 천장 | 가시가 있는 세 층을 지그재그로 내려가기 |
| 5 | 보랏빛 저수지 | 밀도 1.18의 물에서 중앙 저수지 안쪽으로 진입 |
| 6 | 두 바다의 만남 | A·B 스위치를 모두 눌러 0.85·1.18의 물길 연결 |
| 7 | 나선 관측소 | 나선 길의 스위치를 찾아 안쪽 문으로 돌아오기 |
| 8 | 쌍둥이 수문 | A 문을 지나 B 스위치를 찾는 순차 퍼즐, 0.82·1.22 |
| 9 | 침몰한 정비 기지 | 여러 방의 A·B·C 스위치로 중앙 대피소 열기 |
| 10 | 역류 실험실 | 오른쪽에서 왼쪽으로 탈출, 두 스위치와 0.78·1.25 |
| 11 | 심해 탈출 작전 | 세 수문·좁은 길·가시·0.78·1.28을 함께 공략 |

시작 카드에 각 단계의 목표를 표시하고 시작 직후 짧은 안내를 띄웁니다. 스위치·가시·정비소는 게임 화면 안에서 보이며 별도의 설명 패널을 추가하지 않습니다.

### 가시와 누수

붉은 삼각형 가시는 실제 충돌 도형입니다. 닿으면 탱크를 최대 40%로 낮추고 7초 동안 초당 32%의 물을 흘려보냅니다. 잠수정의 평균 밀도가 낮아져 완전히 잠긴 보통 물에서는 떠오릅니다. 물 채우기의 초당 26%보다 누수량이 커서 누수 중에는 채우기만으로 가라앉기 어렵습니다. 외부 부피는 유지합니다. 효과는 주변 액체의 밀도와 잠긴 비율에도 영향을 받습니다.

초록색 ＋ 정비소에 잠수정이 닿으면 즉시 수리하며, 탱크의 남은 물은 그대로 유지합니다. 정비소 없이도 7초 후 누수가 멈춥니다. 같은 가시에 계속 닿으면 재손상될 수 있지만 1.2초의 손상 간격을 두며, 정지 중에는 누수 시간도 멈춥니다. 기존 탱크 계기에 누수 시간을 표시합니다. 탱크는 별도 모델이므로 누수·펌프가 미로 액체의 입자 수나 전체 물량을 바꾸지는 않습니다.

### 스위치와 수문

잠수정으로 원형 스위치를 누르면 녹색으로 바뀌고 작동 상태를 유지합니다. 같은 글자가 붙은 문이 열립니다. `A+B` 또는 `A+B+C` 문은 모든 연결 스위치가 필요합니다. 순차 수문은 앞 문을 열어야 다음 스위치에 접근할 수 있습니다. 모든 수문을 열고 출구에 닿아야 완료됩니다.

닫힌 수문은 잠수정과 물을 모두 막습니다. 열릴 때 Matter.js 충돌체와 액체의 벽·경계 샘플·그림 클리핑을 함께 갱신합니다. 액체 입자의 위치·속도·밀도·물량을 그대로 보존하므로 다른 방으로 순간이동하지 않습니다. 문은 다시 닫히지 않으며 재시작하면 스위치와 문이 초기화됩니다.

밀도 구역은 초기 액체의 성질을 정합니다. 액체가 흐르면 그 밀도와 색도 함께 움직이고 경계에서 섞입니다. 고밀도 액체는 보라색, 저밀도 액체는 금색을 띱니다. 화면 위 ‘물’ 값은 잠수정 주변에 잠긴 액체의 평균 밀도이며 물 밖에서는 `—`를 표시합니다. 값은 게임의 상대 밀도입니다.

## 물과 부력 구현

`core/water.ts`는 입자의 위치·속도·액체 밀도를 저장합니다. 중력으로 이동한 후 밀도 제약을 4회 반복해서 지나친 압축을 줄이고, 약한 응집과 점성으로 입자 뭉침과 분산을 억제합니다. 관성을 유지하므로 기울기를 바꿔도 흐름이 즉시 반전하지 않습니다. 밀도 제약은 [Position Based Fluids 연구](https://matthias-research.github.io/pages/publications/pbf_sig_preprint.pdf)를 참고했습니다.

벽의 고정 경계 샘플과 충돌 처리를 사용하며 물 입자가 벽이나 화면 밖으로 빠져나가지 않도록 합니다. 닫힌 방은 다른 방과 물을 교환하지 않습니다. 입자 수·입자 체적 합·액체 물질의 질량을 유지합니다. 12px 격자는 벽 판정과 관측에 사용하며 물을 칸별 사각형으로 그리지 않습니다.

`render/surface.ts`는 부드러운 입자 밀도장에서 연속적인 등밀도 수면을 추출합니다. Canvas의 벡터 경로를 사용하고 내부 영역을 합쳐 격자 테두리를 표시하지 않습니다. 직전·현재 입자 위치를 프레임 시간에 맞춰 보간합니다. 벽을 가로지르는 밀도장 기여를 차단하고 그림도 실제 통로 영역으로 잘라냅니다. 입자와 계산 배열, 렌더링 버퍼를 재사용합니다.

잠수정과 물은 60Hz 고정 간격으로 계산합니다. 탱크의 상대 밀도는 0%에서 0.65, 50%에서 1.00, 100%에서 1.35입니다. 잠수정 외부 부피는 고정이고 탱크에 따라 질량만 변합니다. 부력은 각 침수 샘플의 액체 밀도를 반영해 중력 반대 방향으로 적용합니다. 저항은 물의 속도에 대한 상대 운동에 적용하므로 중성 부력의 잠수정도 흐름을 따라 이동합니다.

수면과 압력은 경량 게임용 수치 근사입니다. 입자 체적 합은 보존하지만 그려지는 체적에는 근사 오차가 있습니다. 잠수정이 액체를 밀어내는 양방향 상호작용은 후속 확장 범위입니다.

360° 센서는 화면 안쪽 중력 벡터의 두 성분으로 각도를 구하며, 회전 경계와 화면 방향 변경을 이어서 처리합니다. 좌표계와 권한은 [W3C Device Orientation and Motion 표준](https://www.w3.org/TR/orientation-event/)을 참고했습니다.

## 파일 구조

```text
src/core/water.ts        입자 액체, 벽, 밀도 이동, 침수 샘플링
src/core/submarine.ts    Matter.js, 탱크 질량, 부력, 흐름과 저항
src/core/mechanics.ts    가시 삼각형과 스위치·정비소 접촉 판정
src/input/              360° 센서와 터치·마우스·키보드
src/game/game.ts        단계 전환, 고정 시간 루프, 완료와 정지
src/render/             연속 수면, 미로와 잠수정 렌더링
src/ui/view.ts          게임 안의 조작과 단계 선택
src/stages/*.json       11개 미로, 스위치·문·가시·정비소·초기 액체 밀도
src/stages/index.ts     단계 순서
tests/                  액체·밀도·센서·입력·단계·탈출 검사
.github/workflows/      자동 검사와 Pages 배포
```

스테이지의 미로·벽·문 좌표는 `cellSize`의 배수입니다. `densityZones`는 초기 액체 영역의 사각형과 밀도, 이름을 정의합니다. `mission`은 목표, `accent`는 벽의 강조색입니다. `spikes`는 사각형과 `direction`(`up/down/left/right`), `repairs`는 정비소 사각형, `switches`는 `id/label/x/y`, `doors`는 사각형과 `id/label/switches`(필요한 스위치 ID 배열)를 정의합니다. 새 JSON을 `stages/index.ts`에 추가하면 단계 선택과 다음 단계 기능에 반영됩니다.

## 검사

자동 검사 **77개**가 통과했습니다. 주요 범위는 다음과 같습니다.

- 0°·90°·180°·270°에서 액체 이동, 급격한 방향 변경과 관성
- 초기 물 체적, 입자 수, 액체 물질 질량 보존과 벽 충돌
- 정착한 액체 내부의 빈틈과 셀 경계에서의 연속성
- 닫힌 방의 입자·그림 격리와 열린 통로의 이동
- 서로 다른 액체 밀도의 이동·혼합, 잠수정 부력과 물의 흐름에 따른 이동
- 실제 물리 객체를 기울기와 탱크 입력만으로 조작해 첫 미로 탈출
- 11개 미로에서 잠수정 크기와 가시 회피 여유를 반영한 경로, 잠긴 문을 통과하지 않는 스위치 순서
- 가시의 실제 충돌, 누수에 따른 밀도·부력 변화, 누수 정지·수리·재시작
- 복수 스위치 조건, 잠수정·액체 수문 개방과 입자·물량·물질 질량 보존
- 실제 액체 물리에서 첫 수문·가시 천장·최종 세 수문 단계 탈출
- 단계 선택·전환·마지막 완료, 단계 목표와 누수 계기 표시
- 센서 권한 거부·무응답, 두 바퀴 연속 회전, 평평한 자세와 각도 경계
- 터치 해제·취소·동시 입력, 정지·재시작, 전체화면 요청 거절
- 느린 프레임의 계산 몰림 방지, 화면 갱신과 물리 계산 분리, 일시 정지 중 재그리기 중단
- 고해상도 화면의 픽셀 예산, 지속적인 부하 감지, 수면 해상도 변경 전후 물리·물량·부력 표본 일치

센서는 모의 이벤트로 검사했고 실제 Canvas 렌더러로 11개 장면과 열린 수문·혼합 액체 장면을 그려 확인했습니다. 실제 태블릿의 센서와 프레임 속도는 실기기 확인이 필요합니다. HTTPS에서 가로 모드로 시작해 한 바퀴 돌리며 위쪽으로도 물이 이동하는지, 과녁 보정·각도 경계·기기 화면 회전이 자연스러운지 확인하세요. 이후 가시 누수·정비소 수리·복수 스위치·수문 개방 뒤의 물 흐름과 버튼 밖에서 손 떼기를 점검하세요.

## 태블릿 성능

터치 기기에서는 화면을 최대 30회/초, 수면을 최대 20회/초 갱신합니다. 수면 그림의 표본 간격은 12px이며, 일반 기기는 8px·수면 30회/초를 사용합니다. 화면 전체의 픽셀 수를 약 150만 개로 제한하고 배경·벽·가시·정비소는 단계별로 한 번 그려 재사용합니다. 일반 기기도 계산과 그리기에 18ms를 넘게 쓰는 프레임이 누적되면 자동으로 가벼운 설정으로 전환합니다.

입자 수와 부력·충돌 계산은 기존 60Hz 규칙을 유지합니다. 느린 프레임에서는 물리 계산을 최대 두 번 수행하고 밀린 시간을 버려 계산이 계속 쌓이는 현상을 막습니다. 따라서 매우 느린 기기에서는 실제 시간보다 게임 시간이 천천히 흐를 수 있습니다. 대기·일시 정지·완료 화면은 상태가 바뀔 때만 다시 그립니다.

같은 개발 PC에서 1·6·11단계를 각각 180회 시뮬레이션하고 처음 60회를 제외한 결과, 수면 계산과 윤곽 추출에 걸리는 평균 시간은 기존 2.16/2.01/3.14ms에서 태블릿 설정 0.64/0.63/0.82ms로 약 69~74% 줄었습니다. Canvas 합성과 브라우저 동작은 이 측정에 포함하지 않았으며, 교육청 태블릿의 실제 FPS나 30대 수업 환경을 측정한 결과는 아닙니다.

게임은 최초 HTML·CSS·JavaScript 로딩 후 서버 통신 없이 각 기기에서 실행됩니다. 게임 중 움직임이 끊기면 기기 처리 부담을, 첫 접속만 느리면 교실 Wi-Fi와 파일 다운로드를 각각 확인합니다. 새 버전을 배포한 뒤 태블릿에서 페이지를 새로고침하면 변경된 자산을 불러옵니다.

## GitHub Pages

저장소 **Settings → Pages → Source**는 **GitHub Actions**로 설정합니다. `main`에 푸시하면 설치·검사·Vite 빌드 후 `dist`를 배포합니다. Actions에서 배포 workflow를 수동 실행할 수도 있습니다.

`main / (root)`의 원본 소스를 직접 배포하면 개발용 TypeScript 경로를 읽지 못해 빈 화면이 됩니다. Pages에는 빌드된 `dist`가 배포되어야 합니다. Vite의 `base: './'`로 저장소 하위 주소에서 자산을 상대 경로로 불러옵니다. 외부 API 키나 백엔드가 필요하지 않습니다.
